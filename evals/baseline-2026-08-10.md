# Baseline measurement — 2026-08-10

First execution of [`runbook.md`](runbook.md). 16 runs across 4 items. Raw runs are in
`evals/runs/` (gitignored); this file is the scored summary.

## How the runs were produced

| Runbook rule | How it was satisfied |
|---|---|
| 1 — never announce the test | Prompts sent as ordinary requests; no eval framing, no mention of scoring |
| 2 — byte-identical prompt | Prompts extracted programmatically from the fenced blocks in `runbook.md`; only the filename digit substituted (`sed 's#runs/R1/1\.md#runs/R1/<n>.md#'`) |
| 3 — fresh session per run | One `claude -p` invocation per run — a separate process and session, no `--continue`, no `--resume` |
| 4 — clean room | See deviation below |
| 5 — save verbatim | Outputs copied out unedited; see the R1-2 note below |

Invocation: `claude -p "<prompt>" --permission-mode acceptEdits --allowedTools "WebFetch
WebSearch Read Write Edit Glob Grep Skill TodoWrite Task" --output-format json`, cwd = the
run's clone. Default model, default effort. Project settings load normally, so the
`Stop` hook was active in every run.

**Deviation from the runbook — one clone per run, not one shared `evalroom`.** The
runbook says to clone once and start every session in that directory. But runs write
their output *into* that directory (`runs/R1/1.md`), so run 3 of an item would have
runs 1 and 2 sitting on disk in its own working tree — exactly the contamination rule 4
exists to prevent. Each run therefore got a fresh `git clone` of the verified clean-room
template, and its output was copied out afterwards to `runs/<item>/<n>.md` for scoring.
Clean room verified: the template clone of `a7c86e6` contains 30 tracked files, none of
them a prior analysis.

**One recovery.** R1 run 2 wrote its review to an absolute path (`/tmp/evalrooms/R1-2/
runs/R1/2.md`, which resolved to `C:\tmp\...`) instead of the relative `runs/R1/2.md`.
The review itself completed normally; the file was recovered verbatim from that path. This
is a path-resolution quirk of that run, not a content defect, and not something the items
measure.

Cost and wall time: **$22.72**, 16 runs, 54–585 s each (concurrency 4, ~24 min total).

## Per-item findings

**R1 — reproducibility is at the label boundary, not in the analysis.** Three Accept, two
Minor; every run is within one step on the spine. The two Minor runs both cite the same
concrete reason — no locatable ethics/consent statement — and run 4 says outright it
"would have been Accept for a standard research article." So the runs do not disagree
about the evidence; they disagree about whether a missing disclosure section is a revision
condition or a caveat. This is the predicted result in the runbook's "Reading the result"
section: high adjacent, imperfect exact, verdict-label boundary underspecified.

Substantively the five runs converge hard: all five trace the primary via the PMC mirror
(PMC7092803, 4–13 distinct URLs each), all five credit the paper's explicit
Koch's-postulates disclaimer as calibration rather than hedging, and the recurring findings
are the same two — the market-exposure-selected sampling frame, and the missing
ethics/consent statement.

**R2 — 5/5 exact agreement, and the classification is more negative than the item
anticipated.** `items.md` predicted the skill's own Phase 7e language ("unsafe for clinical
recommendation outside deficiency states") and flagged *Established fact* or *Refuted* as
calibration failures in either direction. All five runs land on **Likely false** — one step
from Refuted, not the failure band but adjacent to it. Every run reaches it the same way:
the claim names *healthy adults*, the large purpose-built RCTs in that population are null,
and the positive pooled signal comes from trials in older, frail, institutionalised, or
deficient populations, which is a different claim. Every run says so explicitly and
classifies the narrower claim separately.

This is a real finding about the item, not a defect: the runs are not calling vitamin D
useless, they are refusing the population substitution. But it means the R2 baseline is
*Likely false*, and `items.md`'s expectation should be updated to match what the skill
actually does with a population-mismatched claim.

**F1 — the control passes cleanly.** 3/3 *Established fact*, zero uses of
`(deferred, fragile)` anywhere in any of the three runs, no Phase 6c failure mode invoked
against the central classification. The discipline declines to fire on well-warranted
consensus. This is the answer to the question F1 exists to ask, and it is the reassuring one.

**F3 — the retrieval gate is deterministic.** 3/3 `# Review Stopped: Original Article Not
Found`. Zero occurrences of Article Map, Sourcing Audit, Evidence Load Test, Findings, or
Journalistic Verdict across all three. Each run independently searched, found the live
`rotterdamschecourant.com` domain, fetched it, established it carries nothing from 2019,
and stopped. Cheapest item to run (54–95 s, $0.46–0.69) and the one with a single correct
behaviour — a good candidate for running on every skill change.

## What this baseline does and does not license

- **Adjacent agreement is 1.000 on both reproducibility items.** Synthesis is not
  diverging; verdict-label assignment is.
- **Exact agreement of 0.600 on R1** is the cost of having no evidence-state → verdict
  decision table in `peer-review`. The disagreement is entirely "is a missing ethics
  statement Accept-with-caveat or Minor" — a rule, not a judgement, could settle it.
- **High agreement cannot be read as correctness.** The README already states this ceiling:
  a stable method and a stable bias score identically here. R2's 5/5 is either a
  well-calibrated skill or five runs sharing one corpus. S1's prior-inversion is what
  distinguishes them, and S1 is still unrun.
- **F2 was not run** (drift canary, answer printed in the skill file). **S1** still needs
  the two prior-inverted Nord Stream runs. **S2** is still unpopulated.

## Defects found and fixed

This run surfaced two harness defects. Both are fixed; neither was in a skill.

**1. `score.py extract_verdict` resolved multi-label verdict lines by label length.** Long
labels (`Provisionally accepted`, `Well-supported finding`, `Load-bearing assumption`) beat
short ones (`Refuted`, `Contested`, `Minor`, `Accept`) regardless of which was being
asserted. Runs that classify both a claim and an explicitly narrower variant on one line —
which the `scientific-fact-classification` template encourages — were the systematic case,
and it changed two of the four numbers reported above. Now resolved by earliest position,
with a length tie-break retained so `Reject-resubmit` is not read as `Reject`.

**2. The Stop hook's article-review preflight treated a bare `## Findings` heading as proof
that a review had been produced.** `## Findings` is in the review template, but it is also
an ordinary heading — this eval scorecard tripped it, and the hook demanded an
original-article access line for a document that reviews no article. The four other markers
(`# Journalistic Article Review:`, `## Article Map`, `## Sourcing Audit`,
`## Evidence Load Test`) are distinctive to the template and still fire alone;
`## Findings` now counts only alongside an anchored review signal — a `## Specialist Checks`
or `## Journalistic Verdict` heading, or a `**Verdict:**` line carrying the skill's own
vocabulary. Corroborators are deliberately anchored rather than bare phrases: "right of
reply" and "quote context" appear in prose that merely discusses the method, which the hook
is designed not to fire on.

Fixed in both `.claude/hooks/` and `.codex/hooks/` copies. `evals/test_hook_preflight.py`
covers nine cases against both — four that must block, five that must not — including the
false positive above and a methodology-discussion turn.
